API Mayem v1

Pour les services qui intègrent Mayem, et pour ceux qui réutilisent ses données. Mise à jour le 21 novembre 2026.

Adresse : https://mayem-api.mayem.workers.dev, contrat OpenAPI 3.1

En bref

  • L'API publie des fichiers statiques, en lecture seule : les packs de langue (les traductions validées), le script d'intégration et de quoi les vérifier.
  • Elle ne reçoit jamais le texte de vos pages. La traduction se fait sur l'appareil de l'usager, avec le moteur Mayem.
  • Chaque traduction publiée a été validée par deux locuteurs. Les montants, dates, numéros, références et noms ne sont jamais traduits : une traduction dont les chiffres diffèrent de l'original est rejetée.
  • Chaque pack et chaque script porte une signature de l'équipe Mayem (ECDSA P-256). Vérifiez-la avant tout usage.
  • Une version publiée ne change jamais. Dans un produit livré, citez une version précise ; latest sert à explorer.

Intégrer Mayem en une ligne

Pour proposer la langue à vos clients sans leur demander d'installer une extension. Le script contient déjà les packs : une fois chargé, il ne fait plus aucune requête, ne stocke rien et n'envoie aucun texte de la page.

  1. Récupérez le script et vérifiez-le avec l'outil de l'intégrateur (voir plus bas). La dernière version et sa valeur d'intégrité sont dans /v1/script/index.json. 
    node mayem-verifier.mjs https://mayem-api.mayem.workers.dev/v1/script/<version>/mayem.js --sortie public/js/mayem.js
  2. Servez le fichier depuis votre propre site et ajoutez une ligne à vos pages : 
    <script src="/js/mayem.js" integrity="sha384-…" data-langue="bum" defer></script>
    data-langue reçoit le code de la langue de départ, par exemple bum pour le bulu. L'attribut integrity empêche le navigateur d'exécuter un fichier modifié.
  3. C'est tout. Un bouton Mayem apparaît sur la page : l'usager passe à la langue choisie, et revient au texte d'origine quand il veut.

Le fichier s'utilise tel quel : le modifier rompt l'accord avec l'équipe Mayem, et le navigateur refuserait de toute façon de l'exécuter. Avant de toucher la page, Mayem revérifie encore le pack ; un pack refusé laisse la page intacte.

Ce que le script garantit

  • Seules les traductions validées s'affichent ; une phrase inconnue reste dans sa langue d'origine.
  • Les montants, dates, numéros et références restent exactement ceux de votre page.
  • Aucun champ de saisie n'est lu ni modifié.
  • Les textes ajoutés après le chargement sont traduits aussi, y compris dans les Shadow DOM ouverts.
  • La page doit être servie en https : le calcul d'empreinte utilise Web Crypto.

Un pack refusé émet aussi l'événement mayem-refus sur document (detail : { langue, raisons }) : vous pouvez afficher votre propre message.

Politique de sécurité (CSP). Autorisez le script lui-même dans script-src, par son origine ou son empreinte. Le bouton Mayem a sa propre balise <style> : si style-src interdit le style en ligne, utilisez data-bouton="non" et votre propre bouton.

Vérifier ce que vous recevez

L'empreinte prouve qu'un fichier n'a pas changé ; la signature prouve qu'il vient de l'équipe Mayem. N'importe quel serveur peut recalculer une empreinte, aucun ne peut imiter la signature.

Sans écrire de code

L'outil de l'intégrateur fonctionne avec Node 18 ou plus récent, sans aucune dépendance. Enregistrez mayem-verifier.mjs et mayem-core.js dans un même dossier, puis :

node mayem-verifier.mjs https://mayem-api.mayem.workers.dev/v1/script/<version>/mayem.js --sortie public/js/mayem.js
node mayem-verifier.mjs https://mayem-api.mayem.workers.dev/v1/packs/bum/<version>.json --sortie src/packs/bum.json

Rien n'est écrit si l'empreinte, la signature ou l'intégrité ne correspond pas. Les clés de confiance sont inscrites dans l'outil : avant le premier usage, comparez leur identifiant à celui que l'équipe Mayem vous a communiqué.

Dans votre code

import { verifierSignature } from './mayem-core.js';

// Clés à inscrire dans votre appli, plutôt qu'à relire en ligne à chaque fois
const cles = (await (await fetch('https://mayem-api.mayem.workers.dev/v1/cles-publiques.json')).json()).cles;
const erreurs = await verifierSignature(pack, cles);
// [] : le pack est intact et signé par l'équipe Mayem

Le script est signé octet par octet : sa fiche signature.json donne la signature et la valeur d'intégrité sha384, à vérifier avec verifierOctets.

Les adresses de l'API

Toutes les adresses se lisent par une simple requête GET, depuis n'importe quel site. Une version figée se garde un an en cache ; latest.json, les index et les clés sont revalidés à chaque fois. Les exemples s'ouvrent directement.

Sans clé connue, la réponse est 401. L'équipe Mayem ne garde pas les clés elles-mêmes, seulement leur empreinte ; une clé retirée est refusée partout en une minute au plus. Seules les phrases validées par deux personnes sortent, sans aucun nom.

Le moteur, pour vos applis

Le moteur Mayem (mayem-core.js) est un module ES sans dépendance, pour navigateur, Node, React Native ou serveur. Ses fonctions sont pures : ni accès à la page, ni réseau. Il reçoit un texte et un pack, il rend un résultat.

import { traduire, verifierSignature } from './mayem-core.js';

if ((await verifierSignature(pack, cles)).length) throw new Error('pack refusé');
const resultat = traduire('Votre solde est de 25 000 FCFA', pack);
// resultat.statut === 'ok' : afficher resultat.sortie
// resultat.valeurs : ['25 000 FCFA'], recopiées telles quelles dans la traduction
statutÀ afficher
oksortie : la traduction validée
non_verifieLe texte d'origine ; categorie permet d'afficher une étiquette validée
rejeteLe texte d'origine : la traduction aurait changé un chiffre
testRien en production : traduction pas encore validée, visible en mode test seulement

Quand sens vaut 'reconnu', la phrase n'était pas mot pour mot dans le corpus, mais elle a exactement le sens d'une phrase validée (même négation, même temps, même personne, même sens de l'argent, mêmes valeurs) : c'est la traduction validée de cette phrase qui s'affiche. Il est conseillé de le signaler à l'écran.

Versions et garanties

  • Une version publiée ne change jamais : mêmes octets, même signature. Une correction donne un nouveau numéro (0.8.3 devient 0.8.4) ; une phrase ou un terme ajouté ou retiré aussi (0.8.3 devient 0.9.0).
  • Les identifiants de phrases (id) et de termes (ref) ne changent pas de sens ; une phrase retirée n'est jamais réutilisée.
  • Un champ ajouté au pack est facultatif pour les lecteurs ; un champ retiré change le chiffre majeur.
  • Les fonctions du moteur gardent leur signature tant que le chiffre majeur de Mayem ne change pas.
  • Les premières versions (jusqu'à 0.5.3) sont au format 1, avec la traduction dans un champ nommé bulu ; les suivantes sont au format 2, avec le champ cible. Un lecteur refuse un format qu'il ne connaît pas.

Contrats : OpenAPI 3.1 pour les adresses, JSON Schema pour les packs.

Conditions d'utilisation

  • Le code et les données appartiennent à l'équipe Mayem, tous droits réservés. Tout usage se fait dans le cadre d'un accord avec l'équipe Mayem ; l'accès pourra devenir payant.
  • Les fichiers officiels s'utilisent tels quels, sans modification.
  • Pas de copie, de revente, de redistribution, ni d'entraînement d'un système de traduction sans accord écrit.
  • Mention obligatoire : « Données linguistiques : Équipe Mayem ».
  • Aucune donnée personnelle : chaque phrase est validée par deux relecteurs de l'équipe, désignés par des codes ; leurs noms ne sont jamais publiés.

Pour obtenir un accord ou une clé d'accès, écrivez à l'équipe Mayem à l'adresse de contact indiquée sur la page de l'extension, dans la boutique des extensions de votre navigateur.
